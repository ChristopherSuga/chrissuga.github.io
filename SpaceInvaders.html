Overview

Space Invaders is a remake of the classic 1978 arcade game, developed in C# on the Azul engine framework. The project was designed as a deep dive into object-oriented design patterns, applying over a dozen patterns across the game's systems.

Every major system from enemy management, bullet firing, collision handling, to rendering was built with a specific pattern in mind. The result is a codebase that is highly modular, easy to extend, and straightforward to debug.

Patterns like Object Pooling and Priority Queue target runtime performance, while Composite and Iterator handle the enemy grid hierarchy and traversal. Command and Template keep input and game loop logic clean and reusable.

Design Patterns

Singleton

Ensures a single instance of core managers such as textures, images, sprites, and sound in order to be accessible globally without polluting the namespace.

Factory

Centralizes enemy and shield creation. Swapping out entity types or adding new ones requires no changes to calling code.

Object Pooling

Objects were returned to the pool when no longer needed, and retrieved from it when required, avoiding the overhead of constantly creating and destroying them.

Composite

The Composite Pattern organized the game world hierarchy, letting us treat groups of objects as single entities. The AlienGrid contained AlienColumns which contained individual Aliens, allowing us to handle the entire grid as one unit for movement and collision detection, while still being able to traverse down to individual Alien-level collisions when needed.

Iterator

Custom iterator traverses all of our composite trees without exposing their internal structure, keeping update and render loops clean and decoupled.

Command

We combined the Command Pattern with TimerEventMan to encapsulate actions like movement, animation, and sound as command objects executed at scheduled times.

Template

The Template Pattern let us define common logic in base classes while allowing subclasses to customize specific behavior without altering the overall structure.

Proxy

The Proxy Pattern let us create lightweight proxies referencing a single shared RealSprite. Each GameSpriteProxy stores only position and scale, delegating rendering to the RealSprite when needed, reducing memory usage and improving performance.

Adapter

Adapters wrap Azul engine interfaces so game logic never depends directly on the framework, keeping core systems portable and independently testable.
