Overview

This engine was built incrementally across multiple milestones as part of the Real-Time Software Development course at DePaul University. Every core system was implemented from scratch in C++ with DirectX 11.

The scene graph is built on a PCS (Parent-Child-Sibling) tree, allowing game objects to form hierarchical relationships. Transform matrices compose down the tree each frame, with scaling, rotation, and translation applied in the correct order and multiplied against the parent's world matrix.

The engine's infrastructure follows a consistent manager/node pattern using doubly linked lists managed by a base manager class, covering shaders, cameras, meshes, and game objects alike. The camera system supports multiple cameras with full projection and view matrix management.

Key Systems

PCS Tree Scene Graph

All game objects live in a Parent-Child-Sibling tree. Forward and reverse iterators traverse the hierarchy without loops. All traversal logic is embedded in insert and remove operations.

Hierarchical Transforms

Each game object composes Scale, Rotation, and Translation matrices and multiplies against its parent's world matrix each frame, enabling complex nested motion like orbiting child objects.

Camera System

Multiple cameras managed through CameraNodeMan. Each camera owns its projection and view matrices as heap-allocated pointers with full constructor/destructor lifecycle management.

Custom Math Library

All engine math is powered by a custom-built library with no external dependencies. Includes Vec3, Vec4, Mat3, Mat4, and dedicated Rot, Scale, and Trans matrix types, used throughout the engine for transforms, camera math, and shader constant buffers.

Shader Pipeline

Vertex and pixel shaders compiled and managed through ShaderObjectNodeMan.

Game Object Behaviors

Specialized subclasses such as GameObject_Spin, GameObject_OrbitParent, and GameObject_Orbit demonstrate the scene graph with live spinning, and orbitting.
