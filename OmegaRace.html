Overview

Omega Race is a remake of the classic 1981 arcade game, rebuilt as a networked two-player experience using the Azul engine framework. The project focused on building a robust real-time networking layer from scratch rather than relying on high-level abstractions.

The network layer uses Lidgren.Network over UDP with a data-driven message queue architecture. Messages are polymorphically serialized by type, player input, missile firing, mine placement, collision events, and state sync were each routed to the appropriate delivery method and channel.

To reduce garbage collection pressure, all messages are managed through a pooling system using generic MessagePool<T> instances, avoiding per-frame allocations during gameplay. Client-Side Prediction/Dead-Reckoning keeps movement smooth even under network jitter.

Key Systems

Message Queue Architecture

Data-driven queue with DataMessage as an abstract base. Each message type carries its own serialization logic and delivery metadata channel, reliability, and recipient scope.

Message Pooling

Generic MessagePool<T> instances managed by a central MessagePoolManager, eliminating per-frame heap allocations and reducing GC pressure during gameplay.

Time Sync & Prediction

Cristian's algorithm for clock synchronization between peers. Dead-reckoning client prediction keeps remote player movement smooth under variable network conditions.

Strategy Pattern

Swappable network strategies — NormalStrategy, RecordStrategy, and PlaybackStrategy — allow the game to record and replay sessions for debugging and testing.

Box2DX Physics

Ships, missiles, and mines are all Box2D bodies. Collision events are serialized and sent over the network to keep both clients in sync without re-simulating physics on the client side.

Two-Player Networking

Peer-to-peer UDP session over Lidgren.Network. Unreliable sequenced delivery for high-frequency input, reliable ordered delivery for one-time events like collisions and game state changes.
